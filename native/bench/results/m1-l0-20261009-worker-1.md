# L0 micro benchmarks: first run on worker-1 (2026-10-09)

**`non-idle`** (16 §13.5): the fleet worker and Global Runtime were running,
other agents were building and testing in sibling worktrees, the 1-minute
load average was 4.2–9.7, and the run was outside the 01:00–07:00 window.
These numbers are a first baseline and before/after anchors for this sitting
only. They are not regression or gate evidence. 01 §6 M1 step 7 reads L0
only as before/after A/B.

## Conditions

- Host: worker-1, Apple M4, 4P + 6E (10 logical), 16 GiB, macOS 26.2
  (25C56); facts in `m1-host-facts-20261009-worker-1.md`.
- Toolchain: rustc 1.89.0 (29483883e 2025-08-04), the workspace's default
  `bench` profile (opt-level 3, no LTO, 16 codegen units, default
  `target-cpu`); criterion 0.8.2 (default features off,
  `cargo_bench_support`).
- Benches: commit `b67fac66` on `ws/bench`
  (`native/crates/{pmb-core,pmb-book,pmb-replay}/benches/*.rs`).
- QoS: every bench process ran under `taskpolicy -c utility` (the 16 §13.5
  rule for `non-idle` runs). The effective core type was not recorded.
- Page cache: warm (criterion warm-up 3 s before each measurement).
- Load average (1 min), sampled every 10 s, 37 samples: min 4.22, median
  5.41, max 9.67. It rose from about 5 to about 9 at 12:32:30, during the
  `file_to_tape` and `decimal_parse` groups.

## Observations (to re-check in the window)

- The noise is large. A second pass of the two `heavy-1` decode benches at
  12:35 (load 8.6–8.9) gave `columns16` 272 ms (+78% against 145 ms) and
  `file_to_tape` 430 ms. Only idle-window numbers can rank options.
- Average-size markets decode in about 460–480 ns per row (`file_to_tape`),
  the same order as the m1-ivan scratch figure (16 §2.2: 68.9 ms for an
  average 132,813-row market, about 520 ns per row). For the fixture markets
  the reader costs about the raw 16-column decode plus the decimal parse.
- `heavy-1` in `file_to_tape` (430–520 ms) is about twice the 16 §2.2 scratch
  figure (231 ms), while its raw column decode (145 ms) and parse (58 ms) are
  not. Either load (the jump started during this group) or a per-row cost of
  the reader that grows with row size. Re-measure idle before acting; the
  `phase-timers` profile of `heavy-1` (16 §13.4) will split it.
- The book apply costs about 80–90 ns per recorded event including both
  outcomes' tops. 16 §2.2 measured 79 ns per row for parse and apply on a
  1,001-slot ladder. The parse alone is about 27 ns per string here (about
  4.8 strings per row on `heavy-1`), so apply and tops cost more on this
  10,001-slot ladder with the BK-7 bit than in the scratch prototype.
- Top-of-book changes (BK-7, price or size at the best): 17.9% of `heavy-1`
  events and 16.3% of one fixture market, consistent with 16 §2.2's 16.3%.
- `mul_div` (i128 path) costs about 3 ns. `format_micros` allocates (59 ns);
  it is an output-path function, not a hot-loop one.
