# Protocol audit 2026-07-08--01

## Verdict

The protocol is in the best shape it has been: one role, one home per
concept, a lifecycle diagram that matches the schema invariants, and
`research:check` enforcing the cross-file rules. It is runnable as-is. The
remaining risk has shifted from epistemic (how results are judged) to
operational: the new autonomous continuous session will collide with its
environment — the repo's own git-workflow instructions contradict the
protocol's branch policy, and the judging tool depends on a dashboard that
nothing requires to be running. The single most important problem is A1: the
very first submission of every autonomous session hits two contradictory
instructions about pushing to `main`.

## Findings

### A1 — Root CLAUDE.md forbids exactly what the branch policy requires

- **Status:** ✅ FIXED (mechanism corrected later the same day) — the original generated `--settings` file was verified empirically NOT to apply claudeMdExcludes (CLI-flag scope is not honored for that key). Isolation now lives in the committed `strategy-research-protocol/.claude/settings.json` and every protocol session starts from that folder (scripts cd there before launching Claude). Verified by probe: root CLAUDE.md absent, protocol AGENTS.md present. EXCEPTION note in root CLAUDE.md stands.

- **Severity:** high
- **Category:** flaw
- **Where:** `CLAUDE.md` (repo root, "Git workflow" — "Direct push to main
  is blocked. Always: 1. Create a branch … 3. Open PR … 5. Merge") vs
  `strategy-research-protocol/AGENTS.md` ("Branch policy — Research sessions
  commit directly on `main` and push before submitting remote-worker
  backtests").
- **Problem:** Every researcher session loads BOTH files. Root CLAUDE.md
  says direct pushes to `main` are blocked and mandates the branch→PR→CI
  cycle; AGENTS.md says commit directly on `main` and push (workers track
  `origin/main`). An autonomous session must either disobey CLAUDE.md
  (push main) or stall the loop with a PR+CI round-trip per submission —
  undefined which. Recent research commits on `main` without PR numbers
  (e.g. `52d5438`) show direct push actually works, so CLAUDE.md's claim is
  also factually stale for this repo's owner.
- **Fix:** One line in root `CLAUDE.md`'s git-workflow section: "Exception:
  research sessions driving `src/strategies/research/` commit and push
  directly to `main` per the branch policy in
  `strategy-research-protocol/AGENTS.md`." No protocol change needed.

### A2 — Judging depends on a running dashboard; the fallback is a phantom

- **Status:** ✅ FIXED — dashboard on :3051 is a required precondition (SESSIONS.md, OPERATOR.md); sessions never start it; phantom fallback removed from getBacktestResults.md.

- **Severity:** high
- **Category:** flaw / missing-link
- **Where:** `strategy-research-protocol/tools/getBacktestResults.md`
  (Implementation: `curl http://localhost:3051/...`; If It Fails: "use the
  underlying database query path or start the dashboard");
  `strategy-research-protocol/AGENTS.md` (Session preconditions — no
  dashboard requirement); `strategy-research-protocol/OPERATOR.md` §0 item 4
  ("Dashboard for eyeballing results" — sounds optional).
- **Problem:** The only implementation of the judging read is the dashboard
  API on `:3051`, but nothing requires the dashboard to be running before an
  autonomous session starts. When the curl fails mid-judgment, the suggested
  fallback — "the underlying database query path" — is defined nowhere; a
  bypassPermissions session will invent ad-hoc SQL or start servers on its
  own.
- **Fix:** Add "dashboard running on :3051 (`npm run dashboard`) — required
  for judging" to AGENTS.md Session preconditions and mark OPERATOR §0 item
  4 as required, and delete the phantom "underlying database query path"
  sentence from getBacktestResults.md (replace with: "start the dashboard,
  then retry").

### A3 — The autonomous session has no stop bound: runaway cost and context

- **Status:** ✅ FIXED (user decision: full autonomy, no checkpoints) — hard runaway brake at 200 judged experiments per session in the Researcher session contract.

- **Severity:** medium-high
- **Category:** flaw
- **Where:** `strategy-research-protocol/modules/Researcher.md` (Session
  contract: "stop only when the family is validated or killed, or nothing
  is actionable"); `strategy-research-protocol/STAGE-GATES.md`
  (`minExperiments: 20`, roadmap ≥ 5 ideas, Researcher may extend the
  roadmap).
- **Problem:** A family is typically neither validated nor killable for
  dozens of experiments (empirical kill needs ≥20 evaluated + exhausted
  roadmap). As written, one `researcher.sh` launch may legitimately run for
  days: unbounded spend, a context window that eventually degrades or
  truncates mid-family, and no operator checkpoint after the initial
  proposal review. Resumability makes stopping free — but nothing ever
  stops.
- **Fix:** Two sentences in the Session contract: "Also stop after judging
  ~3 experiments in one session, or when your context grows long — stopping
  is free, the next launch resumes from files." Optionally a `MAX_EXPERIMENTS`
  env in `researcher.sh` (new knob — cost, needs user approval; the
  two-sentence rule alone is enough).

### A4 — `research:check` is all-families; parallel sessions trip over each other

- **Status:** ✅ FIXED — parallel-session rules in the Researcher session contract (foreign check failures are not yours; pull --rebase on rejected push).

- **Severity:** medium
- **Category:** flaw / confusing
- **Where:** `strategy-research-protocol/scripts/research-check.ts` (iterates
  every folder, exit 1 if ANY family fails);
  `strategy-research-protocol/modules/Researcher.md` (run `research:check`
  after every step; "Never touch another family's files");
  `strategy-research-protocol/OPERATOR.md` §2 ("Several families in
  parallel: one terminal per family").
- **Problem:** With two autonomous sessions in parallel, family A's session
  can see `research:check` FAIL because of family B's transient state (e.g.
  B inside its legal one-missing-log-entry window plus an active
  experiment). A's contract gives no rule for a failure it is forbidden to
  fix — it may stall or, worse, "fix" B's files. Parallel sessions also race
  on `git push` to `main` (non-fast-forward) with no pull/rebase guidance.
- **Fix:** One sentence in Researcher.md's Session contract: "`research:check`
  failures in OTHER families are not yours — if your family is ok, note it
  and continue; on a rejected push, `git pull --rebase` and push again."
  (A `--family` filter for research-check would be cleaner but is a new
  mechanism — cost, needs user approval.)

### A5 — The freeze rule (bias containment's keystone) is still unenforced

- **Status:** ⏭️ SKIPPED by user decision — threat model corrected: the gate lives in STAGE-GATES.md outside family files, so softening successCriteria cannot mint validation (see "The two bars" section added to STAGE-GATES.md). Revisit only if a champion swap looks suspicious.

- **Severity:** medium
- **Category:** flaw
- **Where:** `strategy-research-protocol/modules/Researcher.md` (Bias
  containment: hypothesis/successCriteria "frozen once `running`");
  `strategy-research-protocol/MEMORY.md` (same, as writer rule);
  `strategy-research-protocol/scripts/research-check.ts` (no such check —
  it validates only current-state shape).
- **Problem:** Since the Evaluator merge, the entire defense against
  moving-the-goalposts rests on this one rule, and it is doctrine only: a
  session that rewrites `successCriteria` after seeing results produces a
  FAMILY.json that passes `research:check` cleanly. Long autonomous sessions
  with no human reading every diff raise the odds of silent drift. (Known
  and deferred by user decision — recorded here so it stays visible.)
- **Fix:** ~50 lines in research-check.ts: for every non-queued experiment,
  `git log` the FAMILY.json for the commit where its status first became
  `running` and diff `hypothesis`/`successCriteria` against today's values.
  New mechanism — cost, needs user approval; until then it stays a
  documented contract.

## What is good (do not touch)

  at climb end") now matches the schema invariant `stageReached == highest
gateLog go` — the old contradiction is gone.
- One Home Per Concept table in AGENTS.md + the dedupe: rules genuinely live
  in one place; GLOSSARY is definitions-only.
- `research:check`'s cross-file invariants (log-before-acting window,
  batchUid prefixes, champion validity, coverage-vs-stage) are real teeth,
  not documentation.
- LESSONS.md entries are dense, numeric, and genuinely transferable — the
  compounding asset is compounding.
- The file structure after the merges (21 files, single-word names, modules/
  rules/ tools/ with one job each).

paragraph each); A5 when the user approves the git-history check.
