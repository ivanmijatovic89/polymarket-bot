# Protocol audit 2026-07-08--04

## Verdict

Still healthy; the three new angles found five real items where the first
fifteen findings found none. The most important is a direct consequence of
the (correct) session-isolation decision: at least one load-bearing engine
fact — the TechnicalIndicators warmup env var — now exists ONLY in the root
CLAUDE.md that sessions can no longer read, so a TA-based strategy would
backtest silently wrong. The rest are small: an unnamed typecheck command,
an undefined "family metadata" trigger, and two slow-burn accumulation
issues. Runnable as-is; D1 should be fixed before any TA-flavored family is
proposed.

## Findings

### D1 — Isolation cut sessions off from the TA-plugin warmup env var

- **Status:** ✅ FIXED — warmup env documented in ENGINE.md (plugin bullet) and runBacktest.md Inputs.

- **Severity:** medium
- **Category:** flaw / missing-link
- **Where:** root `CLAUDE.md` ("Set `BACKTEST_WAIT_FOR_TECHNICAL_INDICATORS=1`
  when using the TA plugin" — excluded from research sessions since the A1
  isolation fix) vs `strategy-research-protocol/ENGINE.md` (plugin snapshot
  semantics — no mention) and `tools/runBacktest.md` (no mention). Grep:
  zero occurrences of the env var anywhere under
  `strategy-research-protocol/`.
- **Problem:** SCOPE.md explicitly allows plugin snapshots as strategy
  inputs. A family built on the TechnicalIndicators plugin would be
  backtested WITHOUT the warmup env, producing degenerate indicator values
  — and the session has no reachable document telling it the env exists.
  Silently wrong evidence is the worst failure class this protocol has.
  This is the general post-isolation risk instance: any research-relevant
  fact living only in root CLAUDE.md is now invisible to sessions.
- **Fix:** One line in ENGINE.md's Strategy Runner / plugin paragraph:
  "Backtests using the TechnicalIndicators plugin must run with
  `BACKTEST_WAIT_FOR_TECHNICAL_INDICATORS=1` or indicator values are not
  warmed." Plus a sentence in `tools/runBacktest.md` Inputs. (A one-time
  sweep of root CLAUDE.md for other research-relevant facts is part of this
  fix; the TA env was the only one found this pass.)

### D2 — "Typecheck enough" names no command a session can run

- **Status:** ✅ FIXED — step 10 names the command: `npx tsc --noEmit` from the repo root.

- **Severity:** medium-low
- **Category:** confusing
- **Where:** `strategy-research-protocol/modules/ProposeFamily.md` step 10:
  "Typecheck enough to catch API errors. Do not run a backtest." No
  typecheck command exists anywhere under `strategy-research-protocol/`;
  the repo's command reference (root CLAUDE.md) is excluded.
- **Problem:** An isolated autonomous session must invent the invocation
  (`npx tsc --noEmit`? which tsconfig? lint instead?). Inventing commands
  is exactly what the tool-doc discipline exists to prevent.
- **Fix:** Name it once in step 10: "`npx tsc --noEmit` (repo root
  tsconfig) — fix type errors in your new `.ts` before finishing."

### D3 — "Family metadata changed → rebuild INDEX.json" is undefined

- **Status:** ⏭️ SKIPPED by user decision — the trigger moments are already listed in MEMORY.md update triggers; revisit only if a stale-INDEX dedup ever bites.

- **Severity:** low-medium
- **Category:** confusing
- **Where:** `strategy-research-protocol/MEMORY.md` (update trigger:
  "family metadata changed → rebuild INDEX.json") and
  `modules/Researcher.md` Final Self-Check ("INDEX.json rebuilt if family
  metadata changed") vs `scripts/buildStrategyIndex.ts` (INDEX carries:
  status, coreIdea, duplicateKeys, retryOnlyIf, verdictSummary, champion,
  championMetrics, championStageReached, tags).
- **Problem:** "Family metadata" is never defined. A champion promotion
  mid-research changes INDEX content (champion + championMetrics) but a
  session can reasonably read "metadata" as only status/kill/validate — and
  ProposeFamily then dedups against a stale champion picture.
- **Fix:** One clause in the MEMORY.md trigger: "family metadata = any
  field INDEX.json carries (status, champion + its metrics, verdictSummary,
  retryOnlyIf, duplicateKeys, tags)".

### D4 — LESSONS.md grows forever and is required reading

- **Status:** ⏭️ DEFERRED by user decision — let LESSONS.md accumulate for now; curate later when it grows.

- **Severity:** low
- **Category:** simplify (time angle)
- **Where:** `strategy-research-protocol/LESSONS.md` (append-only, "entries
  are never edited or deleted"; required reading for ProposeFamily and
  before every experiment spec). Currently 75 lines after one family —
  fine today; unbounded by design.
- **Problem:** In steady state (dozens of families × several lessons each)
  the mandatory read grows to thousands of tokens per session with no
  curation rule — the compounding asset slowly becomes a compounding tax.
- **Fix (no new mechanism):** One line in the LESSONS.md rules: "When this
  file grows past ~150 lines, the USER curates: supersede/merge stale
  entries into denser ones (append the merged entry, mark the old ones
  superseded). Agents never do this." Keeps append-only for agents; gives
  the human a sanctioned compaction path.

### D5 — Session logs pile up in the repo root, including dead-role relics

- **Status:** ✅ FIXED (docs) — OPERATOR.md §5 notes that session logs in the repo root are gitignored scratch, deletable anytime; the stale evaluator-\*.jsonl relics are left for the user to delete (untracked files, unrecoverable once removed).

- **Severity:** low
- **Category:** simplify (environment angle)
- **Where:** `scripts/researcher.sh` / `propose-family.sh` (LOG default:
  `researcher-<family>.jsonl` in the CWD = repo root); repo root currently
  holds `evaluator-maker-favorite-*.jsonl` relics of the deleted Evaluator
  role. `.gitignore` line 69 (`*.jsonl`) keeps them out of git — verified,
  so the clean-tree invariant is safe — but nothing ever removes them.
- **Problem:** One log per family per role accumulates indefinitely in the
  repo root; stale files from removed roles linger and confuse ("is the
  Evaluator still a thing?").
- **Fix:** Delete the stale `evaluator-*.jsonl` files now, and add one line
  to OPERATOR.md §5 Periodic maintenance: "delete old `*-<family>.jsonl`
  session logs in the repo root when done with them (they are gitignored
  scratch)."

## What is good (do not touch)

  (latency, fees, MATCHED-vs-MINED) — D1's env var was the only missing
  load-bearing fact found in the CLAUDE.md sweep.
- All fifteen prior findings remain fixed; no regressions from the fixes.
