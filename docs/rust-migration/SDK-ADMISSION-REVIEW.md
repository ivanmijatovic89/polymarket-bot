# Native SDK and admission review

This is a bounded implementation checkpoint against TypeScript reference `07245602d6ff9bca0dcdf772134cba3dd227526c`. It does not certify a native strategy, production replay/live job, fleet execution or a speed multiplier. All 64 whole integration requirements, 73 registered strategies and 374 observed artifact versions remain pending or in progress.

## Implemented and checked

Integrated validation passes 89 native tests, 47 client/process tests, all-target Clippy with warnings denied, Rust formatting, binary build and strict checking of nine TypeScript comparison programs. Four test-only fixture drivers are intentionally ignored by ordinary `cargo test` and executed by the differential runners. Reports bind the actual executable, pinned source, fixture/input identities and wrappers; deliberate comparator mutations prevent empty/truncated/renamed outputs from passing.

Typed records store schema-bound scalar slots and generic ordered properties in the same metadata arena. Direct and generic writes share one authoritative property; absent properties differ from own `undefined`, and replacement values retain type/identity. The graph handles BigInt primitives, UTF16 keys, sparse arrays, record/metadata cycles and collection without a detached JSON mirror. Six Portfolio record schemas exist, but financial accounting still uses its previous typed representation; those schemas do not yet prove Portfolio alias parity.

The frame cursor applies a child only when the preceding awaited callback finishes and retains immutable historical payloads. Admission distinguishes synchronous callbacks from deferred callbacks, including ready futures; queued rejection and fresh direct-frame recovery follow the pinned reference. Serial dispatch captures per-entry state before admission, preserves FIFO, recovers after entry failures and settles the receipt before tail finalization. Its owning executor must actively drive admission and serial dispatch; merely awaiting a receipt does not drive an owner. Full runner processing and scheduling tests remain required.

Portfolio probes now inspect typed snapshot numeric fields before JSON can erase infinities/NaNs. Finite values, infinities, signed zero and path/presence stay exact. Derived NaN payload/sign compare by Number class because ECMAScript does not prescribe an observable unique NaN byte encoding; see [Number type](https://tc39.es/ecma262/multipage/ecmascript-data-types-and-values.html#sec-ecmascript-language-types-number-type) and [NumericToRawBytes](https://tc39.es/ecma262/multipage/structured-data.html#sec-numerictorawbytes). This narrow rule applies only to the direct numeric snapshot probe, not arbitrary equality or opaque metadata.

## Review findings

| Finding                                                              | Disposition                                                                                                                                                                                                                                                                                                                                                         |
| -------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Logical JSON encoded strings used directly as admission keys         | Repaired: decode actual logical JSON before BigInt conversion; retain binary64 numeric behavior and UTF16 strings.                                                                                                                                                                                                                                                  |
| Both comparison drivers discarded prior admitted rows on late errors | Repaired: retain the prefix outside the failure catch. New cases assert exact error and prefix boundaries independently.                                                                                                                                                                                                                                            |
| Native JSON parsing admitted part of a failing rowgroup              | Repaired: materialize and validate the entire rowgroup before its first admission. Corruption in either row of the later group leaves exactly two previously admitted rows.                                                                                                                                                                                         |
| Zero-length JSON footer bounds rejected                              | Repaired: skip empty statistics like the pinned reader. Valid rows remain admissible.                                                                                                                                                                                                                                                                               |
| Normalized crate statistics discarded malformed deprecated bounds    | Repaired: validate all four raw Thrift footer bounds during open, before priming any file. Both deprecated min/max cases fail before admission.                                                                                                                                                                                                                     |
| Data-page JSON statistics were not checked                           | Repaired: validate raw page-header bounds lazily at rowgroup load, retaining first-group zero-prefix and later-group two-prefix failures.                                                                                                                                                                                                                           |
| Callback oracle allowed both empty or wrong-identity responses       | Repaired and independently reviewed: bind full counts/identities to source fixtures, guard native source file membership, and reject 13 deliberate mutations.                                                                                                                                                                                                       |
| DECIMAL keys fell back to zero                                       | **Unmet P2-PARQUET-4.** Actual parquetjs DECIMAL precision12 values decode as Numbers, while the current reader falls back. Precision4 on physical INT64 additionally uses contiguous INT32 half words within pages. Durable actual outputs and portable reproduction are under `evidence/parquet-decimal-pending/`. Scalar low-word conversion would be incorrect. |

The reader retains sequence-primary ordering with timestamp-secondary/file-index ties, arbitrary-width BigInt keys, positive local receipt clocks and explicit pop/refill separation. It opens all files before priming and terminates the session on refill failure. It owns one decoded rowgroup at a time. JSON page-statistics validation currently reads compressed column bytes separately; that IO and all later preparation work must be included in the final benchmark, and can only be optimized while preserving these boundaries.

## Required next integration

Authoritative Portfolio maps and retained fill/split/order/history records must move into the shared arena. Snapshot membership containers must be separate from authoritative map membership while sharing record identities; replacements must preserve stale-reference behavior. Raw account envelopes/payloads must be allocated once before queue admission, with processing and logging reading current slots rather than stale copies. Private commitment bookkeeping stays part of the same accounting core.

Actual SDK context and plugins still require local mutable wrappers over retained historical payloads, prototype/assignment behavior, frozen capital/outer wrappers and weak-key capture semantics. Plugin `snap[p.id]` can invoke the `__proto__` setter. Captured WeakMap values that reference keys require ephemeron reachability; weak keys plus permanently rooted values would leak. These contracts remain required.

The final typed source envelope must retain BigInt sequence values and nonfinite receipt Number values. A Serde diagnostic DTO cannot be their authority. The current frame source DTO is only a bounded foundation. Historical WS replay also decodes/selects messages and then passes `JSON.stringify(selected)` through the engine: this creates fresh identities, converts nonfinite numbers to null and normalizes negative zero. A native typed projection must preserve that seam without reparsing hot JSON. Feeding selected values directly to the engine would diverge.

Complete replay modes, native strategy/schema/artifact execution, full shared runner/OrderManager, live connections/signing/reconciliation/rotation, every supported caller, persistence/fleet integration, four-device non-production validation, release/rollback and final alternating end-to-end benchmarks remain required. No production caller has switched; the executable advertises description/aggregation only. Previous benchmark multipliers remain experimental.
