# Arena — vision

> Status: DRAFT — idea capture, nothing built yet. This file is the short
> version; the full design (RULES.md, commons/, competitor workspaces) comes
> after it is agreed.

## What

A competition between AI models — Fable 5, Opus 5, GPT 5.x, Kimi, Grok, … —
all working on **one single strategy**, on **BTC 15m only**, until it is
profitable, running live, and earning real money. No breadth: one strategy,
one market, improve it forever.

## Why this shape

- Previous protocols explored wide (edge-spaces, strategy families). This one
  optimizes a fixed target — every experiment is comparable, progress is
  measurable, and there is one definition of winning: live PnL.
- Models today are smart enough to design their own methodology. The human
  defines only the **invariants** (the constitution); models self-organize
  everything else.
- Multiple independent models attacking the same problem gives free
  replication: a finding two different models confirm is real evidence.

## Structure (one protocol, internal territories)

```
protocols/arena/
  RULES.md                  # invariants — what no model may ever violate
  commons/                  # shared, so nobody re-discovers the basics
    ENGINE.md               #   what the engine can/can't do
    OPS.md                  #   fleet facts: workers, launch commands, backtest speed
    knowledge/<id>.md       #   one FILE per finding (concurrent-write safe)
    bugs/<id>.md            #   one file per bug report
    tools/                  #   shared tools; anyone may add, nobody may break
  strategies/<model>/       # registry-discovered, ids arena-<model>-*
  competitors/<model>/      # each model's private journal/state — exclusive write
```

## Core rules (to be formalized in RULES.md)

1. **Evidence or it didn't happen.** Every knowledge/bug entry carries the
   exact repro (backtest command + run id, verifiable in the DB), the author
   model, and a status: `unverified → confirmed-by-<other-model> → refuted`.
   Decisions may build only on `confirmed` entries.
2. **Standardized scoring.** Fixed eval set, out-of-sample windows,
   leaderboard generated by a shared tool from DB run ids — never
   self-reported.
3. **Shared fleet, fair quotas** — no model may starve the others' backtests.
4. **Harness-neutral rules** (not every model reads CLAUDE.md), model stamped
   on every commit/journal unit.
5. The usual protocol rules: everything on main, own folder only, shared
   `src/` changes via PR, DRY_RUN stays on until the human says otherwise.

## End goal

Strategy profitable in honest backtests → supervised live (small size) →
real money. Then keep improving it.
