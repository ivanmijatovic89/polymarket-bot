# DECISIONS — design forks and why

Each entry: context → options → decision → rejected-and-why.
Newest at the bottom.

---

## D1 — One operating role (Scientist) + fresh-context Judge, not a multi-role split

**Context.** The old system splits work across ProposeFamily / Researcher
roles with stage-gate documents. The failure mode a role split guards against
is self-graded homework: the session that built a strategy also judges its
results and is motivated (by narrative momentum, not intent) to see an edge.

**Options.** (a) Mirror the two-role split; (b) one Scientist role, with
mechanical bias protection (pre-registration + frozen decision rules) and a
fresh-context Judge subagent that issues verdicts from the spec + results
alone; (c) fully autonomous single role, self-judging.

**Decision.** (b). The protection that actually works is structural, not
organizational: the decision rule is written and committed *before* results
exist, and the entity applying it has no memory of building the strategy.
A fresh-context subagent gives exactly that property at near-zero cost, per
`docs/reference/prompting-claude-fable-5.md` ("fresh-context verifier
subagents tend to outperform self-critique"). A second *session role* adds
coordination surface (locks, handoffs, session scheduling) without adding
protection beyond what the fresh-context Judge already provides.

**Rejected.** (a) — coordination overhead and context fragmentation; the role
boundary is enforced socially rather than mechanically. (c) — self-judging is
the exact bias channel the charter says to protect against.

## D2 — Evidence thresholds as formulas (t-statistics), not fixed market counts

**Context.** The charter demands: "How much data buys how much belief?
Justify every threshold from first principles." Fixed counts ("run 500, then
3000") are cargo cult unless tied to effect size.

**Decision.** Express every belief threshold as a t-statistic on per-market
PnL: t = (mean/std) · √N = quality · √N, where quality is exactly the
engine's persisted `qualitySystem` (mean/std over all markets, skipped = 0).
Stage sizes are then *derived*: the N needed to resolve the minimum effect
size worth trading at the required t. Defaults are recorded, but the formula
is the rule; the defaults are recomputed when the measured cost structure
changes. Full derivation in `protocol/EPISTEMOLOGY.md`.

**Rejected.** Fixed counts without power analysis — they either waste compute
on effects too small to matter or pass noise on effects the sample cannot
resolve. Also rejected: bootstrap/bayesian machinery beyond the t-frame for
v1 — per-market PnL across thousands of independent 15m episodes is close to
the iid case where the t-statistic is honest; sophistication can come later
and would slow the loop tonight.

## D3 — Time-split holdout, fixed at registration, one-shot

**Context.** Grading on the data used for iteration overfits. Need an
out-of-sample discipline that survives the fact that one agent controls
everything.

**Options.** (a) Random market split; (b) interleaved calendar split (even/odd
weeks); (c) time split: exploration = older markets, holdout = the most
recent block, boundary frozen inside the pre-registered spec.

**Decision.** (c). The objective is *durable* edge — the failure that kills
live deployment is regime drift, and only a chronological holdout tests
survival into data that is genuinely "later" than everything iterated on.
The boundary (a specific `market_start_ms`) is written into the experiment
spec at registration; the holdout run happens once, after the exploration
verdict, and its result is final for that strategy version. Re-rolling the
holdout after seeing it = new strategy version, new experiment, and the old
holdout becomes exploration data (it is burned).

**Rejected.** (a) random split — leaks regime: adjacent 15m windows from the
same day land on both sides, so the "holdout" is not out-of-sample in the
sense that matters. (b) interleaving — same leak, milder; also complicates
extend-based coverage growth, which is contiguous-by-time in the engine
(`--extend` grows from the covered edge).

## D4 — The registry is append-only files; runs are labeled, never renamed

**Context.** Files are the only memory that survives a session. The engine's
own durable records are `backtest_runs` rows keyed by `batch_uid` label and
immutable `cmd`.

**Decision.** One directory `protocol/registry/experiments/` with one file
per experiment (`EXP-NNN-slug.md`), append-only sections (spec first, then
run records, then verdicts). `batch_uid` for every run is the experiment id
plus stage (`EXP-012-probe`), so DB rows and registry files cross-link
without a lookup table. An `INDEX.md` table (one line per experiment) is
regenerated by a tool, never hand-edited.

**Rejected.** A JSON/DB-backed registry — harder for a fresh session to skim,
and the DB is the *engine's* memory, not the protocol's; mixing them couples
protocol state to schema migrations. Rejected renaming/moving experiment
files on status change — breaks cross-links from DB comments and old
sessions' notes.

## D5 — Mechanism-first idea ledger; dedupe by mechanism, not by indicator

**Context.** Idea generation is cheap for an LLM; the scarce resource is
compute and holdout data. Unstructured idea lists degenerate into re-testing
the same mechanism under different indicator names.

**Decision.** Every idea entry must state: (1) the *mechanism* — who is on
the other side of the trade and why they systematically lose (in one of a
small closed set of mechanism classes, e.g. "stale quotes after fast moves",
"overpriced tails near expiry", "spread capture in quiet regimes",
"UP/DOWN sum mispricing"); (2) a falsifiable prediction about *recorded*
data; (3) the cheapest experiment that could kill it. Two ideas with the
same mechanism class and the same prediction target are duplicates, whatever
the parameterization. Priority = expected information per compute-hour:
mechanism novelty × plausibility × (1 / test cost).

**Rejected.** Indicator-first ideation ("try RSI", "try Bollinger") — it
multiplies parameter cells without multiplying mechanisms, which is exactly
the curve-fit target the charter forbids.

## D6 — Simulator-bias classification is a mandatory verdict field

**Context.** The engine study (CAPABILITIES.md §4) shows the simulator is
knowably optimistic in specific ways (full-size maker fills on touch-through,
zero market impact, free instant split/merge, costless settlement) and
knowably pessimistic in others (worst-queue, 156 bps taker fee on every
taker fill).

**Decision.** Every verdict must classify where the measured edge sits
relative to these biases: a strategy whose PnL is dominated by maker fills
in thin books, or by large size, is flagged `simulator-favored` and cannot
pass confirmation on backtest evidence alone (it needs a live paper phase —
out of scope tonight, but recorded as the required next step). This is a
field in the spec template so the judge cannot skip it.

**Rejected.** Applying a numeric "haircut" to maker PnL — any constant would
be an invented cost, which the charter forbids; classification + escalation
to live validation is honest about what backtests can and cannot prove.

## D7 — Strategies live in fable-lab/strategies/, injected via run-backtest.ts; all runs local --sequential

**Motivating evidence (evolution governor).** Charter v2 made evidence
backtests allowed but "local `--sequential` only" and reaffirmed "write ONLY
inside `fable-lab/`" + "no worker-fleet submissions ever". The protocol as
designed in U3-U8 assumed fleet runs and strategies under
`src/strategies/fable/` — mutually impossible under those constraints:
the pre-commit hook (`fable-lab/.hooks/pre-commit`) blocks commits outside
`fable-lab/`, evidence runs require committed code, and the engine registry
auto-discovers only `src/strategies/**` (`strategyRegistry.ts:24`,
`Dirent.isDirectory()` does not follow symlinks). Concrete friction, verified
this session.

**Options.** (a) Copy committed fable-lab strategy files into an untracked
`src/strategies/fable/` at run time; (b) a wrapper entry point that mutates
the exported `strategyRegistry` object in-process (valid because the
`--sequential` path replays entirely in-process, `backtest.ts:706`,
`runSingleMarket.ts:116` resolves via the same module instance), then
imports the standard CLI; (c) ask the operator to relax the hook.

**Decision.** (b) — `fable-lab/tools/run-backtest.ts`. Zero writes outside
`fable-lab/`, tree stays clean (correct `commit_sha` on every per-market
row), reproducible from any checkout of the branch. The wrapper hard-refuses
non-`--sequential` invocations (queue workers would re-resolve strategies in
processes that never ran the wrapper). `tools/submit.ts` appends
`--sequential` to every stage and routes through the wrapper. Validated:
2-market smoke with injected `fable-fixture-noop` replayed 100,850 events
(batchUid EXP-000-wrapper-smoke, 2026-07-09).

**Rejected.** (a) — writes outside fable-lab/ (against the charter's write
scope) and leaves the tree dirty with untracked files during evidence runs.
(c) — not mine to decide; the hook is the operator's mechanism.

**Consequence for stage sizing.** No fleet parallelism: replay throughput is
~1.1s/market (no-op strategy, local data) on this machine, so a 500-market
probe is ~10-30 min in the background and the full exploration window
(~14k markets) is hours — acceptable, sized per EPISTEMOLOGY §2/§3;
re-measure with a real strategy and record here if materially different.

## D8 — submit.ts pins the execution-model env for every stage

**Motivating evidence (evolution governor).** EXP-002 smoke (2026-07-09)
produced one-legged FOK "pairs" losing money on a riskless-by-construction
trade. Debug replay showed order submission at t and execution at t+145ms:
the repo's ambient `.env` sets `BACKTEST_LATENCY_DELAY=140`, silently
applied to all runs — including the first EXP-001 probe, launched assuming
the engine default of 0ms (CAPABILITIES §4).

**Decision.** `tools/submit.ts` sets `BACKTEST_LATENCY_DELAY=0` and
`BACKTEST_LATENCY_JITTER=0` explicitly for every stage (the `lat` stage sets
its own delay; `??=` preserves it). The anchor for decisive stages stays
0ms — the engine default the epistemology was derived under; latency
realism enters through the mandatory {0,150,300} sensitivity curve
(EPISTEMOLOGY §5), not through an ambient constant. The first EXP-001 probe
(launched 140ms, killed at ~365/500 before any row was persisted) is void;
relaunched pinned.

**Rejected.** Adopting 140ms as the decisive-stage anchor — it is exactly
the kind of invented constant the charter forbids (nobody measured 140ms
for OUR execution path); the sensitivity curve carries that information
honestly. Also rejected: editing `.env` (outside fable-lab write scope).

## D9 — Exogenously truncated random samples are judged, not voided

**Motivating observation:** EXP-001 probe run 301 was killed at 379/500 by a
session-end SIGTERM; all 379 markets persisted cleanly (0 failures).

**Decision:** when a `--random` evidence run is truncated by a cause that is
independent of market content (session death, machine restart), the persisted
prefix is a valid random sample of its size and is judged under the stage's
rules at that N. The truncation and its cause are recorded in the Runs entry.
Rejected alternative: void-and-relaunch (wastes replay-hours and, for
`--extend`-based repair, would replace random sampling with oldest-first
selection — a worse sample, not a better one). Truncation that correlates
with content (e.g. crash on a specific market) still voids the run.

## D10 — Evidence runs launch detached from the session

**Motivating observation:** two probe launches killed by session-level
SIGTERM (LESSONS E8) — the launcher was a child of the session's process
group.

**Decision:** every evidence run (probe/main/lat/grid/holdout) is launched
in its own session so it survives session death; the launching session then
polls the log/DB. macOS ships no `setsid` binary, so the launcher is
`node fable-lab/tools/detach.mjs <log> <cmd...>` (Node `detached: true`
performs setsid(2)); env pins are set on the launcher process and inherited.
Smokes may stay foreground (they are ~30s and never evidence). This changes
how commands from `tools/submit.ts` are invoked, not what they contain.

## D11 — Grid cells run on random subsamples, not the full window

**Motivating observation:** EXP-001's neighborhood is 8 non-primary cells;
at the measured full-window cost (~13.6k markets ≈ 2h+ each under
contention) the grid alone would cost >24 replay-hours, while the battery
judges grids on SIGN-SMOOTHNESS only (EPISTEMOLOGY §5.1). At probe-measured
q≈0.16, a 2,000-market random sample resolves the sign at |t|≈7; even
q≈0.05 gives |t|≈2.2 — ample for a shape judgment.

**Decision:** `submit.ts --stage grid` now passes `--random` through; grid
cells run `--random --limit 2000` by default (larger only if a cell's sign
is ambiguous, i.e. |t| < 1). The PRIMARY cell's decisive numbers still come
from the full-window main run; lat runs stay full-window because they are
paired with main by construction. Rejected alternative: oldest-first
`--limit` truncation (time-biased subset — December-only markets would
confound smoothness with regime).

## D12 — Wrapper clamps quality columns at the drizzle driver boundary

**Motivating observation:** grid run 315 (EXP-001 cell entryAfterSec=600,
minAsk=0.95) crashed at final persist: a daily segment with near-identical
played pnls produced qualitySystem ≈ avg/std > 1e8, overflowing
DECIMAL(14,6) (`Out of range value for column 'quality_system' at row 60`).
The persist is ONE transaction — all 2000 markets were rolled back (~50 min
of replay lost). `computeQuality` guards only std === 0 exactly.

**Decision:** `tools/run-backtest.ts` overrides `mapToDriverValue` on
`backtestRunSegments.qualitySystem/qualityTrade`, clamping |q| to 1e6 and
mapping non-finite values to NULL. |q|=1e6 and |q|=1e9 carry identical
decision information ("degenerate, near-zero variance"); no protocol
statistic distinguishes them. Rejected alternatives: patching the engine
(off-limits — write only inside fable-lab/), ALTERing the shared DB schema
(diverges from drizzle migrations, affects the other research system).
Residual risk: the already-running main/lat runs predate the guard; their
~95 played markets/day make a degenerate day unlikely (probe's 136 days
were all fine), accepted rather than burning 2h of completed replay.
