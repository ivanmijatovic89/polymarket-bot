FINDINGS:
1. **MAJOR** — `fable-lab/tools/calib2.ts` (lines 54–57, 131–145) vs `fable-lab/knowledge/CALIBRATION-2.md` (Confirmation requirement, step 2): the BINDING reserve-confirmation protocol mandates "a one-shot calib2.ts read of the reserve log," but the committed tool cannot execute that read. Gate 1 hard-aborts (exit 2) unless the parsed totals equal the discovery log's 104,776 / 52,388-per-side, and the only bypass (`--outcomes`) is refused for non-"synthetic" paths and would anyway replace the DB join. The reserve log will necessarily have different totals. So if discovery produces a candidate, the confirmation step requires modifying the tool AFTER the discovery table has been seen — exactly the post-hoc-modification window the header declares a protocol breach. Compounding it: the frozen sub-windows (→Dec 2025, Jan, Feb 2026) are all before the reserve window (≥2026-03-01), so every reserve candidate would print `CANDIDATE-demoted(subwindow-inconsistent)` (all windows n=0), while the registration's reserve bar deliberately omits sub-window consistency — the tool's flag output on the reserve read is undefined/misleading. Fixing this is free now; after the read it is a credibility cost.
2. **MINOR** — `fable-lab/tools/calib2-selftest.ts` (fixture design, lines 39–89): no fixture move lands on a bucket edge (−0.02, −0.005, +0.005, +0.02), so a swapped `loInc`/`hiInc` or a `>=`/`>` error in `moveBucketIndex` would pass the selftest undetected; likewise the dedupe-before-drift ordering is not pinned (the planted duplicate duplicates a drift-VALID line; a first-occurrence-drift-invalid + later-valid-duplicate case — where calib.ts's convention discards both — is untested). I verified by inspection that the current code matches the spec's edges exactly (dn2 ≤−0.02, dn1 (−0.02,−0.005], flat open, up1 [0.005,0.02), up2 ≥+0.02; negation-symmetric, partition complete), so this is a drift-protection gap, not a present bug.
3. **MINOR** — `fable-lab/knowledge/CALIBRATION-2.md` (Instrument, lines 48–50): "The DOWN book is an exact mirror … no DOWN-derived move is computed — it would be −move by construction" overstates: the final log has TWO mirror deviants (CAL-001 Results disclosure), one at off=300, an endpoint of pairs (150,300) and (300,450), where the DOWN-derived move genuinely differs from −move. At ≤2 markets in 52,388 this is immaterial, but the registration cites only "amendment #12 / E20" without the two-deviant caveat; verdict wording should carry it.
4. **MINOR** — `fable-lab/tools/calib2.ts` (lines 266–273) / CALIBRATION-2.md gate 3: an EMPTY E14-analog control passes silently ("control OK (empty)"). On the real log an empty [0.90,0.98) pooled control at pair (750,850) would signal a derivation bug, not a benign state. Mitigated: gate 2 (tail n≥30 from the same pooled sample) would trip first for any bug emptying the sample wholesale, and CAL-001's n≈520/516 there makes true emptiness implausible — but the spec never says what empty control means.
5. **MINOR** — `fable-lab/tools/calib2.ts` (line 159): moves are computed as float differences of 4-dp mids with no epsilon at bucket edges; a mathematically-exact-edge move (e.g. 0.505−0.500 = 0.00499999…) can be assigned to the adjacent bucket by FP. Deterministic, tiny, direction-agnostic — same class of exposure CAL-001 accepted for ask buckets — but neither spec nor tool acknowledges it.
6. **MINOR** — `fable-lab/tools/calib2-selftest.ts`: several decision paths are unexercised — subwindow-demotion, minority<30 (both positive-z no-flag and NEG-FLAG(underpowered-E14)), non-empty E14 control, unresolved-outcome exclusion, and the parser-consistency gate's PASS/FAIL branches (only SKIPPED is asserted). Also the guard test leaves `calib2-guardtest.log` behind in logs/ (gitignored; cosmetic).
