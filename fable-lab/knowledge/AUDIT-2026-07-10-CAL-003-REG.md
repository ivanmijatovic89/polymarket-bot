## Findings

1. **minor — statistical convention** — `fable-lab/knowledge/CALIBRATION-3.md` line 95-97 / `fable-lab/tools/calib3.ts` line 67. The frozen bar `z ≥ 3.25` does not satisfy the tail(z) ≤ α/k convention that CAL-001/002 used and that the CAL-002 pre-read audit certified ("tail(3.37) ≈ 3.757e-4 ≤ 0.023/60 ≈ 3.833e-4; 3.36 would not clear"). Computed precisely: tail(3.25) = 5.7703e-4 > 0.023/40 = 5.7500e-4, while tail(3.26) = 5.5706e-4 would clear. Actual FWER bound is ≈ 40 × 5.7703e-4 = 0.02308, not 0.023, and the registration's claim "same total-α convention as CAL-001/002" is therefore slightly false — the bar is on the anti-conservative side of the target for the first time in the series. Effect is negligible (0.35% relative) and both numbers are printed in the registration, but it is free to fix now and a credibility nick after. Concrete fix (pre-read amendment, CAL-002 amendment pattern): either raise the bar to 3.26 in both files (the selftest's designed candidate z = +5.14 and NEG-FLAG z = −5.69 are unaffected), or amend the wording to disclose the direction ("bar exceeds α/k by 2.0e-6 absolute; anti-conservative by 0.35%, accepted").

2. **minor — non-derivable rationale figure** — `fable-lab/knowledge/CALIBRATION-3.md` lines 70-75 (and `DECISIONS.md` D26, rejected alternative (b)): "mid-involved two-segment cells would sit at n ≈ 15-60, resolving nothing at any bar." From CAL-002's PUBLISHED tables, mid-range buckets (dn1+flat+up1) hold ~8.7-12.1% of entries per pair and dn2/up2 ~44% each; under independence a single-mid shape cell (e.g. dn-mid at the late triple) lands at n ≈ 180-380, roughly 5× the claimed range — only the mid-mid cell lands near 15-80. The registration's own standard is "from PUBLISHED numbers only," and this figure is not derivable from them. Worse, the one-shot will print the aggregate mid-excluded entry count (`skippedMid`, plausibly ~15-25k across 10 triple×side combinations), visibly inconsistent with "15-60 per cell" × 50 hypothetical cells ≈ 750-3,000. The exclusion itself remains defensible (at n ≈ 300, the bar is still ≈ 8-9c vs the 2-3c effects in play) — the number is what's wrong. Fix: pre-read erratum re-deriving the estimate (single-mid cells ≈ 180-380 by independence from published fractions, mid-mid ≈ 15-80) and resting the exclusion rationale on the resolvable-|d| bar, not on "15-60."

3. **minor — motivating-evidence range slip** — `fable-lab/knowledge/CALIBRATION-3.md` lines 12-14: "the post-move UP ask is stale-high ≈ 2-2.4c gross at every pair from 300s on (UP dn2 z: −2.23, −3.00, −3.72, −2.90)." Published gross d values are −1.51c (300-450), −1.92c (450-600), −2.43c (600-750), −2.25c (750-850): the 2-2.4c range holds only from ~600s on; at 300-450 it is 1.5c. This is the exact defect class the E21 Judge flagged (reservation 1: "from 300s on" over-claiming) and that the erratum corrected — reintroduced here. Fix: pre-read wording amendment to "≈ 1.5-2.4c gross at every pair from 300s on, 2-2.4c at the late pairs."

4. **minor — vacuous selftest assertion** — `fable-lab/tools/calib3-selftest.ts` line 163: `['gate-reproduction not claimed on synthetic', /^(?!.*gate-reproduction OK)[\s\S]*$/]`. Without the `s` flag, `.*` inside the anchored lookahead cannot cross newlines, so the assertion only inspects the FIRST line of output. Verified mechanically: the regex returns `true` on a string containing "gate-reproduction OK" on line 2. The assertion can never fail on real multi-line output — zero drift protection for the one behavior it names. (Code inspection confirms the tool is correct today: gate-reproduction runs only under `!synthetic && !reserveMode`, calib3.ts line 335.) Fix: replace with `!out.includes('gate-reproduction OK')` via a negated-string check (e.g. assert `out.includes('gate-reproduction OK') === false`).

5. **minor — gate-reproduction PASS path untestable pre-read + live-DB dependence** — `fable-lab/tools/calib3.ts` lines 77-80, 335-351. The new load-bearing gate 2 comparison is exercised in neither PASS nor FAIL mode by the selftest (it is skipped on synthetic input by design and only the real log can match the hard-coded values); a typo in `GATE_EXPECT` would surface only as a spurious ABORT at the one-shot. I hand-verified all eight constants against CAL-002's published Results (tail 0.9869/686 UP, 0.9777/719 DOWN; ctl −1.03/519, −0.59/516) and the `toFixed(4)`/`toFixed(2)` formatting matches calib2.ts's printouts exactly, so no present defect. Residual risk to record: the gate implicitly assumes `telonex_markets.result_id` is unchanged since CAL-002's read earlier today — any DB mutation on a joined slug aborts the read spuriously. The abort fires before any cell table prints (only outcome-free counts precede it), so it is recoverable without a protocol breach; no fix required, but the run log should note this assumption.
