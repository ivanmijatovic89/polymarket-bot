## Findings

**1. MAJOR (D) — the selftest pins only 1 of the 3 frozen statistical families.** All assertions target the monotone screen, gates, filters, and refusal (`signal3-selftest.ts:157-191`). Not one assertion touches the CELL GRID (`signal3-scan.ts:291-318`) or FILL SEASONALITY (`:320-347`) output. A silent breakage there — e.g., the tie-averaged-rank quintile boundary filter at `:302` (with heavy ties a block lands in one quintile and others fall under n=30 and vanish), or the day-of-week formula at `:330` — would still print "0 CANDIDATE" and pass the selftest, and §6's closure conclusion requires "zero candidates in **all three families**." A false-quiet family directly feeds the maker-family tombstone. Fix (legitimate pre-read: adds assertions, changes no scan semantics): plant a non-monotone (U-shaped) quintile effect and a seasonal effect in the synthetic world; assert the flagged cells appear with correct sign, and assert `cellTotal` > 0 and seasonality bins print. I hand-verified the dow formula (`(epochDay+4)%7` → 0=Sunday ✓) and the quintile logic under no-ties, but verification-by-auditor is not a regression pin.

**2. MAJOR (G) — the "mechanical complement gate" is not fully mechanical.** SIGNAL-FILLS.md:138-145: "gate = exclude the adverse sign side / adverse extreme quintiles of the candidate feature" names **two different gates** (half-population sign-side vs extreme quintile(s)) without a selection rule, and "quintiles" (plural) leaves the arity open (q5 only, or q4+q5?). Bullet 2's "tick-avoidable" and bullet 3's non-gateable class ("**e.g.** seasonality-only, …") leave the gateable/non-gateable classification to post-hoc judgment. The complement's predicted EV is +px/(1−p) (§6 last bullet) — p is exactly what this freedom lets you choose after seeing the tables. Fix: append (pre-read, append-only, before the scan runs) a disambiguation: e.g., "monotone CANDIDATE → gate excludes the single adverse extreme quintile per stratum (side determined by the Stouffer sign); cell-grid-only CANDIDATE → gate is exactly the union of flagged cells; gateable ⇔ the feature is computed by the fixture's own tick code path." Any frozen choice works; the choice must predate the read.

**3. MINOR (C/F) — the scan does not mechanically enforce the frozen sample.** No discovery-window epoch guard (`signal3-scan.ts` accepts any epoch; enforcement lives in launch procedure + `signal3-coverage.sh`, which checks totals but not epochs), no coverage-total check, and G2 is **silently** skipped when n<100 (`:245`) while G1's vacuous branch prints a disclosure (`:240`). I verified the actual launch lists are clean, so this is defense-in-depth, not an active defect. Fix: epoch-boundary filter with a printed counter + a vacuous-G2 disclosure line.

**4. MINOR (E28-class) — "selftest 17/17" is false; it is 16.** SIGNAL-FILLS.md:110 and DECISIONS D52 both claim 17 assertions; the file contains 16 `check()` calls and running it prints exactly 16 PASS. This is precisely the lab's recorded defect class (E28: in-log numeric claims not re-grepped against the artifact). Fix: append-only correction in §6b.

**5. MINOR (C) — silent tightening: unregistered n≥200 stratum precondition on families 2 and 3.** Registration §4.2/§4.3 state per-cell n≥30 (and per-stratum n≥200 only for the monotone screen); the scan additionally requires the stratum ≥200 before building quintiles (`signal3-scan.ts:297`) and seasonality bins (`:325`). Harmless at n≈8,100 but it is the "silently over-tightened claim" pattern the audit was asked to hunt. Fix: one disclosure line pre-read.

**6. MINOR (B) — qMidDrift fake-zero leak.** `diag-fill.ts:252-253`: if the tracked quote was placed before any valid UP tick (`midAtQuote` NaN via `prevMid` at `:226`), qMidDrift logs 0.0000 while qAgeSec stays ≥0, so `hasQuoteAttr` remains true and the row enters the qMidDrift test as a fake zero instead of being sentinel-excluded. Rare (requires a quote before the first valid UP book) and scan-side undetectable (0 is a legal value). Disclose; fix the fixture for any future recut.

**7. MINOR (B) — silent fill drop can relabel fillSeq=0.** `diag-fill.ts:254`: a fill arriving while `lastState === null` returns before logging **and before `fillSeq++`**, so the next physical fill is logged as fillSeq=0 — a primary-sample substitution with no counter. Reachable only when a quote exists without any prior valid-UP+DOWN tick; under the mirror-book invariant (CAL-001 am. #12: UP invalid ⟺ DOWN invalid ⇒ no quote) the corner is structurally near-empty, but it is silent if the invariant ever breaks. Fix for future: emit a `[diag-fill-dropped]` counter line.

**8. MINOR (B/doc) — fElapsed is fill-tick information.** The scan maps `fElapsed` from `fTs` (`signal3-scan.ts:191`) — the fill's own timestamp — while the registration claims all 21 features are "causal at the last pre-fill tick" and that "fill-triggering-tick state is deliberately NOT logged." Clock time is knowable in advance, so a time gate is still implementable live; but strictly, `stateTs` was the causal choice. One-line disclosure suffices.

**9. MINOR (C) — "fill seasonality" bins by market start, not fill time.** `signal3-scan.ts:328-330` uses `epochSec` (market open), not `epoch + fTs`; a fill can sit one 4h bin later than its market's open for markets straddling a boundary (≤ ~6% of markets, ≤1 bin, deterministic, outcome-independent). Disclose or note as market-open seasonality.

**10. MINOR (B) — no staleness accounting on lastState.** `lastState` updates only on ticks with valid UP book + DOWN quotes and elapsed<900 (`diag-fill.ts:140,166`), so the "pre-fill" block can be arbitrarily stale; the scan never uses `stateTs` (e.g., report the fTs−stateTs distribution or flag rows staler than N seconds). Causal (never future-leaking), so it dilutes power rather than biasing; worth a printed distribution at read time.

A rerun under a different env silently changes these four features — same ambient-env class as the D8 latency incident. Currently benign; worth pinning in the shard launch recipe.
